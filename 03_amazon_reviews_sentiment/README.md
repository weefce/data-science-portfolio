# Классификация тональности отзывов Amazon Fine Foods

## Описание проекта
Построение модели для автоматического определения тональности отзывов (позитивный/негативный) на основе текста

## Бизнес-задача
Автоматизация обработки отзывов для быстрого выявления негативных отзывов и реагирования на проблемы клиентов

## Ключевые результаты
- **Лучшая модель:** Logistic Regression с балансировкой классов
- **Accuracy: 88%**
- **F1-score (positive): 0.92** - отличное качество для позитивных отзывов
- **F1-score (negative): 0.75** - хорошее качество для негативных отзывов (с учетом дисбаланса)
- **Recall (negative): 83%** - находим 83% негативных отзывов
- **Recall (positive): 89%** - находим 89% позитивных отзывов

## Ключевые выводы
- **Текст - основной источник информации** - признаки полезности, времени и длины текста не показали значимой корреляции с целевой переменной
- **Данные сильно разреженные** - 69% продуктов имеют всего 1 отзыв
- **Базовая логистическая регрессия показала лучший результат** - сложные модели переобучаются
- **TF-IDF эффективнее CountVectorizer** - снижает вес общих слов
- **Pipeline + кросс-валидация** обеспечили корректную оценку без утечки данных
- **Анализ ошибок** выявил основные проблемы: смешанная тональность, сравнительные конструкции и сарказм

## Технологии
- **Библиотеки:** pandas, numpy, matplotlib, seaborn, scikit-learn
- **Методы:** TF-IDF векторизация, ColumnTransformer, Pipeline, кросс-валидация, GridSearchCV
- **Модели:** Logistic Regression, Naive Bayes, Random Forest, LinearSVC


## Особенности подхода

### 1. Выборка данных
Исходный датасет содержит 568,454 отзыва. Для ускорения вычислений взята случайная выборка 30,000 отзывов с random_state=42 для воспроизводимости

### 2. Предобработка целевой переменной
Исходная оценка (Score) имела 5 градаций (1-5 звёзд). На основе EDA принято решение:
- **positive**: оценки 4-5 (положительные отзывы)
- **negative**: оценки 1-3 (негативные + нейтральные)
- **нейтральный класс (3)** исключен из-за размытых границ

### 3. Отбор признаков
EDA показал низкую корреляцию не текстовых признаков с целевой переменной:
- HelpfulnessNumerator: -0.05
- HelpfulnessDenominator: -0.11  
- Длина текста: -0.07
- Временные признаки: незначительные колебания

**Решение:** оставлены только текстовые поля `Text` и `Summary`

### 4. Векторизация и пайплайн
- Использован `ColumnTransformer` для параллельной обработки двух текстовых полей
- `TfidfVectorizer` (max_features=5000 для каждого поля):
  - Учитывает частоту слова в конкретном документе
  - Снижает вес общих слов (good, great, product)
  - Выделяет уникальные слова-маркеры (best, love, bad, awful)
- **Pipeline** объединяет препроцессор и модель, гарантируя отсутствие утечки данных

### 5. Кросс-валидация
Для объективной оценки использована 5-кратная кросс-валидация с метрикой F1-macro, что позволило:
- Корректно сравнить модели без подгонки под один split
- Избежать утечки данных (TF-IDF переобучается в каждом фолде)
- Выбрать лучшую модель по усреднённым метрикам

### 6. Анализ ошибок
Проведён детальный разбор 1118 ошибочных предсказаний (12.4% тестовой выборки):
- **False Positive:** модель посчитала негативный отзыв позитивным
- **False Negative:** модель посчитала позитивный отзыв негативным

## Основные этапы работы
1. EDA - анализ распределений, выявление разреженности данных (69% продуктов с 1 отзывом)
2. Проверка гипотез - связь полезности и оценки не подтвердилась
3. Отбор признаков - удалены все не текстовые признаки (низкая корреляция c целевой переменной)
4. Предобработка - выборка 30 000 строк, бинарная целевая переменная
5. Векторизация - ColumnTransformer с TF-IDF для текста и заголовка
6. Моделирование - Pipeline + кросс-валидация для 4 моделей
7. Выбор лучшей модели - Logistic Regression (F1-macro = 0.83 на CV)
8. Анализ ошибок - разбор ложных срабатываний и пропущенных негативных отзывов
9. Интерпретация - анализ ключевых слов для positive/negative
