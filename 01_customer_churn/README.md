# Прогнозирование оттока клиентов телеком-компании 

## Описание проекта
Прогнозная модель для выявления клиентов с высоким риском оттока с целью проактивного удержания 

## Бизнес-задача
Своевременно выявлять клиентов, которые могут уйти, чтобы предложить им персональные условия и удержать. Основной фокус - на полноту обнаружения уходящих клиентов (recall), так как важнее не упустить уходящего, чем избежать лишних срабатываний

## Ключевые результаты
- **Лучшая модель:** Logistic Regression с порогом 0.474
- **Recall (отток) 85%** - находим 85% уходящих клиентов (ключевая метрика)
- **Precision (отток) 52%** - каждый второй предсказанный реально уйдет (ложные срабатывания допустимы ради высокого recall)
- **F1-score (отток): 0.65**
- **AUC-ROC: 0.85** - модель хорошо разделяет классы

## Топ-факторы оттока: 
1. **Интернет провайдер "Fiber optic"** - самый сильный фактор риска
2. **Временный клиент** - короткий срок + помесячный контракт
3. **Одна подключенная услуга** - максимальный риск (46%), при росте услуг риск снижается
4. **Наличие нескольких номеров** - умеренно повышает риск
5. **Доступ к стриминговым фильмам** - слабо повышает риск

## Защитные факторы
1. **Двухлетний и годовой контракты** - сильно снижают риск
2. **Отсутствие телефона** - снижает вероятность оттока
3. **Долгий срок обслуживания** - чем дольше клиент, тем ниже риск
4. **Наличие онлайн защиты** 
5. **Наличие техподдержки**  

## Ключевые выводы
- **Дисбаланс классов:** ушедших в 3 раза меньше - использованы взвешенные метрики (F1, recall)
- **Feature engineering подтвердил ценность:** созданный признак `temporary_customer` вошёл в топ важных
- **Мультиколлинеарность:** MonthlyCharges коррелирует с Fiber optic, поэтому его коэффициент отрицателен, хотя в EDA видно, что уходящие платят больше
- **ColumnTransformer + кросс-валидация** обеспечили корректную оценку без утечки данных

## Технологии
- **Библиотеки:** pandas, numpy, matplotlib, seaborn, scikit-learn
- **Методы:** OneHotEncoding, StandardScaler, ColumnTransformer, кросс-валидация, RandomizedSearchCV, GridSearchCV
- **Модели:** Logistic Regression, SVM, Random Forest, XGBoost, CatBoost


## Особенности подхода 

### 1. Предобработка данных
- Признак `TotalCharges` приведён к числовому типу, пропуски (новые клиенты) заполнены нулями

### 2. Анализ данных (EDA)
- Выявлен дисбаланс классов 
- Определены ключевые категориальные признаки: Contract, InternetService, PaymentMethod
- Обнаружена разреженность данных: 69% продуктов имеют 1 отзыв
- Проверены гипотезы о влиянии дополнительных услуг на отток

### 3. Feature Engineering
На основе EDA созданы признаки, отражающие группы риска:
- **temporary_customer** - новые клиенты с помесячным контрактом
- **fiber_without_services** - Fiber optic без доп. услуг
- **senior_alone** - пожилые одинокие клиенты
- **num_services** - количество подключенных услуг
- **IsAlone** - одиночки (без партнёра и иждивенцев)

### 4. Моделирование
- ColumnTransformer - подготовка данных без утечки данных  
- 5-фолд кросс-валидация для сравнения моделей  
- RandomizedSearchCV / GridSearchCV - подбор гиперпараметров

### 5. Выбор лучшей модели
- Logistic Regression - лучший баланс (F1=0.61 на CV)  
- Порог 0.474 дает recall 85%  
- CatBoost - близко, но recall ниже (81%)

### 6. Анализ важности признаков
- Топ-5: Fiber optic (+2.36), MonthlyCharges (-2.01), Contract_Two year (-1.74), temporary_customer (+0.76), tenure (-0.74)  
- MonthlyCharges - отрицательный коэффициент из-за корреляции с Fiber optic
